第一代 · 2025.09

v1 grafana_nginx  — 三容器分离架构

┌─── 宿主机 ──────────────────────────────┐ │ │ │ docker: test_nginx1.28 (9699) │ │ nginx WebDAV PUT ← CI 上传 CSV │ │ nginx GET → Grafana 读取 CSV │ │ │ │ docker: dt_watcher │ │ Python 监听 /data/details/sources/ │ │ → 解析 CSV → 追加 catch2Result.csv │ │ → 生成 HTML 报告 │ │ │ │ docker: dt_dashboards (9696) │ │ Grafana + Infinity 插件 │ │ 读取 catch2Result.csv │ │ │ │ /home/kk/catch2_data/data/ 共享挂载 │ └─────────────────────────────────────────┘

✅ 优点

  • 职责分离清晰
  • Grafana 功能丰富
  • 快速验证可行性

❌ 问题

  • 三容器独立维护，顺序依赖启动
  • 三个挂载路径不一致（/data、/opt/catch2_data…）
  • CSV 格式脆弱，无时区语义
  • Grafana dashboard 不持久化，容器重建即丢失
  • Infinity 插件需要外网安装
数据格式 CSV
存储 CSV 文件 + HTML 报告文件
容器数 3 个独立容器
第二代 · 2026.06

v2 grafana_v2.0  — 单容器 + SQLite

┌─── Docker 容器 dt_all ────────────────┐ │ │ │ supervisord（进程守护） │ │ ├── nginx 8080 → 宿主 9698 │ │ │ PUT /details/sources/ ← CI CSV │ │ │ GET /data/ → Grafana │ │ │ │ │ ├── grafana-server 3000 → 宿主 9696 │ │ │ frser-sqlite-datasource 插件 │ │ │ │ │ ├── python watcher (app_catch2/) │ │ │ 监听 /data/details/catch2/ │ │ │ CSV + JSON → SQLite │ │ │ │ │ └── python watcher (app_bm/) │ │ Benchmark 结果处理 │ │ │ │ /data/ ← 唯一挂载点 │ └──────────────────────────────────────────┘

核心改进

🎯 三容器合并为一，supervisord 管理三进程
💾 CSV → SQLite，引入 db.py 结构化存储
🔗 挂载点统一为单一 /data/
📦 整体 tar 打包，支持离线 docker import
➕ 新增 Benchmark 支持（app_bm/）
📄 JSON 格式并行支持（同时保留 CSV）

❌ 残留问题

  • Grafana 镜像体积 1~2 GB
  • Dashboard 仍不持久化（需手动重配）
  • 构建依赖外网（Grafana apt 源）
  • 单平台设计，runs 表无 platform 字段
  • 时区语义不明确，由 Grafana 自行处理
第二代 · 数据层

v2 从 CSV 到 SQLite

v1 CSV 方案

# catch2Result.csv（汇总） time,pass,total 2026-06-23 10:00:00,38,40 2026-06-24 09:30:00,40,40 # /details/html/report-*.html（明细） 静态 HTML 文件，watcher 重启后重建

缺陷

  • 无法按字段查询
  • 重启全量重建，历史易丢
  • 并发写 CSV 不安全
→

v2 SQLite 方案

-- /data/test_results.db runs(id, time TEXT, pass INT, total INT) test_cases(id, run_id → runs.id, num, module, binary, case_name, result TEXT)

改进

  • 结构化查询，关联明细
  • 重启保留历史，run_exists() 去重
  • Grafana SQLite 插件直读
数据流  CI PUT testResult.csv → nginx → /data/details/sources/ → watcher 解析 → db.insertResult() → Grafana SQLite 读取

第三代 · 功能页面

v3 Flask 三页面设计

GET /

首页 Pivot 汇总

读所有 *.db，生成 10 天 × 多平台交叉表。
每格显示 pass/total，点击跳转失败用例 modal。

• 行 = platform / os / arch
• 列 = 最近 10 天（CST）
• 每天只取最新一次运行
• 无数据平台依然显示（空行）
GET /detail/<platform>/<id>

单次运行明细

展示一次 CI 运行的 全部测试用例，支持客户端分页（JS 控制显隐）。

• 列：num / module / binary / case / result
• pass/failed 颜色区分
• 时间展示 CST（utc_to_cst filter）
• 服务端渲染，无 API 请求
GET /platform/<p>?os=&arch=

平台历史趋势

左侧 分页列表（所有历史），右侧 Chart.js 折线图（近 60 天通过率趋势）。

• Chart.js 本地托管，无外网
• 图表数据 JSON blob 嵌 <script>
• 通过率 = pass / total × 100%
• API：/api/detail 返回失败用例 JSON
热更新机制 模板 .html 文件 → docker cp 即生效（Flask 每次请求读文件） |  web.py 修改 → docker cp + kill Flask → supervisord 自动重启，<3s 恢复
第三代 · 技术细节

时区处理 & 数据格式收敛

UTC 存库 / CST 展示

# DB 存储（UTC） time = "2026-07-09T10:00:00Z" # SQL 查询分组（+8h 偏移） date(time, '+8 hours') # Flask 列头 datetime.now(CST).date() # Jinja2 模板渲染 {{ run.time | utc_to_cst }}

好处

  • DB 时区语义明确，不依赖客户端
  • 列头与 SQL 分组结果天然对齐
  • CST 与 UTC 换算只在展示层发生

JSON 唯一格式（去掉 CSV）

{ "platform": "tx82", "os": "linux", "arch": "x86_64", "time": "2026-07-09T10:00:00Z", "summary": { "pass": 120, "total": 125 }, "results": [ { "num": 1, "case": "TestFoo", "result": "pass" }, { "num": 2, "case": "TestBar", "result": "FAILED" } ] }

好处

  • 平台字段直接来自 JSON，无目录解析
  • 删除 csv2html.py / tar.gz 处理逻辑
  • watcher 代码减少约 40%

部署指南

v3 快速部署

构建 & 启动

# 构建镜像 docker build -t dt_v3:1.0 . # 启动 docker run -d --restart=always \ --name dt_v3 \ -p 9696:3000 \ -p 9698:8080 \ -v /home/kk/catch2_data/data:/data \ dt_v3:1.0 # 验证三进程 docker exec dt_v3 supervisorctl status

CI 上传 & 热更新

# CI 推送测试结果 curl -u user:pass123 -T result.json \ http://HOST:9698/details/\ 2026-07-15_10-00-00/testResult.json # 热更新模板（无需重启） docker cp app_web/templates/index.html \ dt_v3:/app_web/templates/index.html # 热更新 web.py（supervisord 自动重启） docker cp app_web/web.py dt_v3:/app_web/web.py # kill Flask PID → supervisord 3s 内重启

离线部署

# 导出 docker export dt_v3 -o dt_v3_1.0.tar # 目标机器加载 docker import dt_v3_1.0.tar dt_v3:1.0 # 启动（import 丢失 CMD，需手动指定） docker run -d --restart=always \ --name dt_v3 \ -p 9696:3000 -p 9698:8080 \ -v /your/data:/data \ dt_v3:1.0 \ /usr/bin/supervisord -n \ -c /etc/supervisor/conf.d/all.conf
